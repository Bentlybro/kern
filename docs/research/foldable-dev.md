# foldable-dev

## Summary
Building a first-class foldable app for Fold8-class devices in 2026 centers on Jetpack WindowManager 1.5.1 (FoldingFeature postures, hinge bounds, WindowSizeClass BREAKPOINTS_V2 with Large/XLarge), Compose Material3 Adaptive 1.2.0-stable/1.3.0-rc01 (ListDetailPaneScaffold, SupportingPaneScaffold, Reflow/Levitate strategies, pane-expansion drag), and Google's renamed "Adaptive" quality tiers (ready/optimized/differentiated). Android 16 (targetSdk 36) ignores orientation/resizability restrictions on sw>=600dp screens with a temporary opt-out that Android 17 (targetSdk 37) removes; Play requires API 36 by Aug 2026 and 37 by Aug 2027. Connected-displays desktop windowing hit GA in Android 16 QPR3 (Mar 2026) on Pixel 8/9/10 and Samsung S26/Fold7/Flip7/Tab S11, and One UI 8's DeX is now built on Android's desktop windowing, so DeX optimization has largely converged with stock multi-window/desktop rules. Samsung specifics: tabletop/Flex Mode is detected via standard FoldingFeature (HALF_OPENED+HORIZONTAL), Fold cover screens run apps normally (continuity is the developer's job), Flip "FlexWindow" third-party apps require Good Lock MultiStar's Launcher widget, and Remote Test Lab offers free remote testing on real Fold hardware including Flex Mode.

## Key facts
- androidx.window stable is 1.5.1 (Nov 19, 2025); 1.6.0-alpha05 (Jun 17, 2026) adds WindowEngagementInfo/EngagementMode.PRECISE_POINTER; window-testing ships WindowLayoutInfoPublisherRule, a FoldingFeature test factory, and ActivityEmbeddingRule.
- WindowManager 1.5 added WindowSizeClass.BREAKPOINTS_V2 with Large (1200-1600dp) and XLarge (>=1600dp) width classes, WindowMetrics from Application Context, widthDp/heightDp/density on WindowMetrics, and auto-save/restore of activity-embedding state.
- FoldingFeature exposes state (FLAT, HALF_OPENED), orientation (HORIZONTAL, VERTICAL), occlusionType (NONE, FULL), isSeparating, and bounds (Rect); tabletop posture = HALF_OPENED + HORIZONTAL, book posture = HALF_OPENED + VERTICAL; WindowInfoTracker.supportedPostures (requires WindowSdkExtensions >= 6) reports SupportedPosture.TABLETOP.
- Compose Material3 Adaptive: stable 1.2.0 (Oct 22, 2025), 1.3.0-rc01 (Jun 17, 2026); artifacts adaptive, adaptive-layout, adaptive-navigation, adaptive-navigation3; AdaptStrategy.Hide/Reflow/Levitate, PaneExpansionState + Modifier.paneExpansionDraggable, NavigableListDetailPaneScaffold, currentWindowAdaptiveInfo(); enable L/XL breakpoints with supportLargeAndXLargeWidth = true.
- NavigationSuiteScaffold is stable in androidx.compose.material3:material3-adaptive-navigation-suite (versioned with material3; material3 stable 1.4.0, alphas at 1.5.0-alpha25 as of Jul 2026).
- Activity embedding (androidx.window.embedding) is the multi-activity/legacy path: SplitPairRule + RuleController, ActivityEmbeddingController.pinTopActivityStack(), draggable DividerAttributes, EmbeddingAnimationBackground, setLaunchingActivityStack; requires manifest property android.window.PROPERTY_ACTIVITY_EMBEDDING_SPLITS_ENABLED=true. New Compose apps are steered to single-activity multi-pane scaffolds instead.
- Android 16 (targetSdk 36): orientation, resizability, and aspect-ratio restrictions are ignored on displays with smallest width >= 600dp (no more letterboxing/pillarboxing); a temporary per-activity opt-out exists. Android 17 (targetSdk 37) removes the opt-out entirely; games (android:appCategory) are exempt. Play deadlines: API 36 by Aug 2026, API 37 by Aug 2027.
- Google's large-screen quality tiers were renamed to Adaptive tiers: Tier 3 'Adaptive ready' (fills window, no letterboxing, state preserved), Tier 2 'Adaptive optimized' (multi-pane layouts, keyboard/mouse/stylus, drag-and-drop), Tier 1 'Adaptive differentiated' (experiences only possible on large screens/foldables, e.g. posture-aware UI).
- Connected-displays desktop windowing reached GA in Android 16 QPR3 (announced Mar 3, 2026) on Pixel 8/9/10 and Samsung S26, Fold7, Flip7, Tab S11: apps run in freeform/maximized windows on external monitors; use Navigation 3 Scene/SceneStrategy and Material 3 Adaptive 1.2+/1.3 prebuilt Scenes; handle dynamic Display changes and per-display density.
- One UI 8's Samsung DeX was rebuilt on Android 16's desktop windowing (Google-Samsung collaboration), so standard resizeableActivity=true + config-change handling covers it; legacy DeX manifest meta-data: com.samsung.android.keepalive.density=true (classic DeX) and com.samsung.android.multidisplay.keep_process_alive=true (DeX dual mode); never declare reqTouchScreen/required touchscreen features.
- Cover screens: Galaxy Z Fold cover display is a normal display (apps just run; continuity across fold/unfold is the developer's job via state restoration). Z Flip cover display ('FlexWindow') does not allow arbitrary third-party apps by default - users must enable them via Good Lock MultiStar's Launcher widget (MultiStar 10.2.13 fixed this after One UI 8.0).
- Stylus: androidx.ink 1.0.0 stable (Dec 17, 2025; 1.1.0-alpha06 Jul 29, 2026) with ink-authoring/-brush/-geometry/-rendering/-storage (+ -compose interop artifacts); InProgressStrokesView gives low-latency front-buffer inking (~4ms class latency via the Jetpack graphics low-latency technique); Android 14+ stylus handwriting works in any text field via IME HandwritingGesture APIs.
- Input/drag-and-drop: keyboard shortcuts surface via Activity.onProvideKeyboardShortcuts/KeyboardShortcutGroup (Meta+/ helper; Android 16 adds user-customizable shortcuts in Settings); Compose keyboard handling via Modifier.onKeyEvent/onPreviewKeyEvent; drag-and-drop via Modifier.dragAndDropSource/dragAndDropTarget (compose-foundation, ClipData-based, cross-app with DRAG_FLAG_GLOBAL) or View DropHelper (androidx.draganddrop).
- Testing: resizable emulator is non-experimental since Android Studio Narwhal feature drop (toggle phone/foldable folded-unfolded/tablet/desktop); Compose DeviceConfigurationOverride (ForcedSize) runs any-size UI tests on one device; window-testing's WindowLayoutInfoPublisherRule fakes FoldingFeatures; Samsung Remote Test Lab is free remote access to 1500+ real devices including Folds with Flex Mode.

## Fold awareness (WindowManager)
Pattern: `WindowInfoTracker.getOrCreate(activity).windowLayoutInfo(activity).collect { info -> info.displayFeatures.filterIsInstance<FoldingFeature>() }` inside `repeatOnLifecycle(STARTED)`. FoldingFeature: `state` (FLAT/HALF_OPENED), `orientation` (HORIZONTAL/VERTICAL), `occlusionType` (NONE/FULL — FULL means a physical hinge occludes content; keep content out of `bounds`), `isSeparating`, `bounds: Rect`. Tabletop = HALF_OPENED+HORIZONTAL (media on top pane, controls below hinge); book = HALF_OPENED+VERTICAL (split panes at hinge x). `WindowInfoTracker.supportedPostures` (WindowSdkExtensions >= 6) checks `SupportedPosture.TABLETOP` capability. Compose helper `collectFoldingFeaturesAsState()` exists in material3-adaptive. WindowAreaController adds rear-display (`transferActivityToWindowArea`, renamed `transferToWindowArea` in 1.6) and dual-screen (`presentContentOnWindowArea`) modes.

## Size classes & M3 Adaptive
WM 1.5 `WindowSizeClass.BREAKPOINTS_V2`: Compact <600, Medium 600–840, Expanded 840–1200, Large 1200–1600, XLarge >=1600dp width. In Compose use `currentWindowAdaptiveInfo()`; scaffolds: `NavigableListDetailPaneScaffold(navigator = rememberListDetailPaneScaffoldNavigator())`, `SupportingPaneScaffold`, generic `ThreePaneScaffold`. 1.1 added `PaneExpansionState` drag-to-resize + `ThreePaneScaffoldPredictiveBackHandler`; 1.2 added `AdaptStrategy.Reflow`/`Levitate`, `preferredHeight`, saveable expansion state, L/XL support (`supportLargeAndXLargeWidth = true`); 1.3-rc adds prebuilt Scenes for Navigation 3 (`Scene`/`SceneStrategy`) and KMP stubs. Fold8-class inner screen (~7.6–8") is typically Expanded when unfolded, Compact-width on the cover display — one adaptive codebase covers both.

## Activity embedding vs single-activity
New Compose apps: single activity + adaptive pane scaffolds (Google's default guidance). Multi-activity apps: activity embedding (androidx.window.embedding) — `SplitPairRule.Builder().setMinWidthDp(600).setDefaultSplitAttributes(SplitAttributes...ratio(0.5f))`, `RuleController`/`SplitController`/`ActivityEmbeddingController.getInstance(context)`, manifest `<property android:name="android.window.PROPERTY_ACTIVITY_EMBEDDING_SPLITS_ENABLED" android:value="true"/>`. WM 1.4 added ActivityStack pinning, draggable `DividerAttributes`, `embeddedActivityWindowInfo()` callback, `setLaunchingActivityStack`; 1.5 auto-saves/restores embedding state across process death.

## Continuity, config changes, multi-resume
Fold/unfold = configuration change (screen size/layout/density); default is activity recreation. Either restore state (ViewModel + rememberSaveable/SavedStateHandle — Tier "Adaptive ready" requires continuity) or declare `android:configChanges="screenSize|smallestScreenSize|screenLayout|orientation|density|uiMode|keyboard|keyboardHidden"` and handle manually. Set `android:resizeableActivity="true"`; in split-screen all visible activities are resumed (multi-resume, Android 10+); use `onTopResumedActivityChanged()` for exclusive resources (camera/mic). Never assume Display == app window: use `WindowMetricsCalculator`/`currentWindowSize()`.

## Quality tiers & letterboxing
Tiers renamed: Tier 3 "Adaptive ready" (fills window portrait+landscape, never letterboxed, state continuity), Tier 2 "Adaptive optimized" (canonical layouts, external input, drag-drop), Tier 1 "Adaptive differentiated" (posture-aware, desktop-class). Android 16/targetSdk 36 ignores orientation/aspect/resizability restrictions on sw>=600dp (temporary opt-out via `PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY`-style per-activity flags); Android 17/targetSdk 37 removes the opt-out (games exempt). Play deadlines: API 36 Aug 2026, API 37 Aug 2027. Camera apps: use CameraX PreviewView/CameraViewfinder to survive arbitrary aspect ratios.

## Samsung specifics
- Flex Mode = standard AndroidX FoldingFeature detection (no separate Samsung SDK needed now); Samsung's Galaxy Z developer docs mirror Google's posture guidance.
- DeX in One UI 8 is rebuilt on Android 16 desktop windowing (Google+Samsung collaboration); optimize for stock desktop windowing and DeX follows. Legacy DeX meta-data: `com.samsung.android.keepalive.density` (classic), `com.samsung.android.multidisplay.keep_process_alive` (dual mode); avoid `reqTouchScreen`/required touchscreen features; handle 8 runtime changes (density xxxhdpi->mdpi, resolution, orientation, etc.). DeX detection via `Configuration.semDesktopModeEnabled` reflection.
- Cover screens: Fold cover display runs apps normally (design for narrow ~Compact width, 120Hz, and fold/unfold continuity). Flip "FlexWindow": third-party apps only via Good Lock MultiStar Launcher widget (user opt-in), not a public 3P app surface; widgets are the sanctioned surface.
- Remote Test Lab (developer.samsung.com/remote-test-lab): free remote control of 1500+ real devices incl. latest Folds, drag-drop APK install, Flex Mode testing.

## Input, drag-drop, testing
Keyboard: `onProvideKeyboardShortcuts()` + `KeyboardShortcutGroup`/`KeyboardShortcutInfo` (Meta+/ helper since API 24; Android 16 adds user-customizable shortcuts); Compose `Modifier.onPreviewKeyEvent`/`onKeyEvent`. Stylus: MotionEvent hover, pressure/tilt; androidx.ink 1.0 (`InProgressStrokesView`, `Brush`/`StockBrushes`, `CanvasStrokeRenderer`, `PartitionedMesh` for erase/select) with front-buffer low-latency (~4ms class); Android 14+ IME handwriting in any text field. Mouse: hover states, right-click context menus, `PointerIcon`. Drag-drop: `Modifier.dragAndDropSource`/`dragAndDropTarget` (onStarted/onEntered/onMoved/onExited/onDrop), cross-app with `DRAG_FLAG_GLOBAL` + URI grants; Views: `DropHelper.configureView`. Testing: resizable emulator (non-experimental, Studio Narwhal FD) toggling phone/foldable(fold-unfold)/tablet/desktop; `DeviceConfigurationOverride(ForcedSize(...))` in compose-ui-test; window-testing `WindowLayoutInfoPublisherRule` to inject fake `FoldingFeature(bounds, TYPE_HINGE, STATE_HALF_OPENED)`; Compose UI Check mode in Studio.
