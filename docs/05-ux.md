# 05 — UX Design

This design is grounded in [research/ux-research.md](research/ux-research.md), which collects real accounts of coding on foldables and phones, and in [research/editor-tech.md](research/editor-tech.md), which sets out the input constraints. The governing insight is that **phones are provably great at reviewing, steering, and terminal work, and raw typing is the weak point**, so the design leads with review, agent and terminal excellence and makes typing as good as Android allows.

## The four display modes

Kern derives the mode from the window size class, the `FoldingFeature` posture and the DeX/desktop state, never from the device type. Transitions preserve exact state, because broken resume is the silent killer of daily use.

### 1. Cover Companion (folded, 5.5" squat 10:16 — one-handed)

This is not a shrunken IDE; it is a purpose-built cockpit:

- **Agent cockpit**: the cover screen tails live agent and terminal output and shows "agent needs you" question cards with approve, deny and reply actions, and push notifications drive re-entry.
- **Git ops**: the user can check status, stage, and commit with an AI-suggested message, then push or pull, which is the loop GitHub Mobile has already proven.
- **Diff review**: only unified diffs are shown, because split diffs fail at this width, and each hunk can be accepted or reverted with syntax highlighting throughout.
- **Status board**: it lists the running sessions, the build results, and the battery and thermal state.
- The layout is a single column with bottom-anchored actions, because the screen is short so vertical space is precious, and the thumb lives at the bottom.
- This mode requires onboarding to enable Samsung's "Continue apps on cover screen", which is what gives inner→cover continuity.

### 2. Unfolded IDE (7.6" 4:3 landscape-first — the main event)

- This mode shows the full VS Code workbench. The default arrangement puts the editor beside a right-or-bottom panel holding the terminal, and leaves the file tree as the workbench's collapsible sidebar, which gives two comfortable columns and never three.
- **Bottom-first chrome**: our native key row and mode controls sit at the bottom, because thumb-reach research shows the top corners are the dead zone, and Material specifies 48dp targets.
- The layout is hinge-aware: when a physical crease is present, Kern offers to align the split to the hinge, putting the editor left and the terminal right in a book-ish grip.
- Touch editing improves on the stock workbench: long-press selection uses the Android `Magnifier`, the key row carries an explicit multi-cursor mode toggle, and tap-gutter breakpoint affordances are sized to 48dp.
- The gesture vocabulary stays tiny, which the research gives as the ceiling: a swipe moves between editor groups and terminal tabs, and two fingers scroll the terminal. Nothing exotic is on offer.

### 3. Tabletop / Flex (half-folded, hinge horizontal — the "laptop")

This is the flagship differentiated mode, and it applies at a 75–115° hinge angle:

- **Top half (vertical)**: the upright half is the content zone and carries the editor or the agent output.
- **Bottom half (flat)**: the flat half is the control zone and carries the terminal with our key row, or the key row with a REPL. Nothing interactive sits on the crease, and the panes align to `FoldingFeature.bounds`.
- This is a *self-contained pocket laptop*: it needs no kickstand and no keyboard, and it works on a train tray. No desktop IDE and no current mobile app does this seriously, so it is genuinely novel territory.
- The implementation repositions the workbench panel through the bridge extension and pairs it with a native bottom surface, and it animates the posture transitions.

### 4. DeX / Desktop (external display or desktop windowing)

- The workbench is already a desktop app, so this mode mostly means *getting out of the way*: it gives full hardware-keyboard fidelity, resizable freeform windows (`resizeableActivity=true`, density-change handling), mouse hover, right-click and pointer icons, and no mobile chrome.
- One UI 9 rebuilt DeX on Android desktop windowing, so if we optimise for stock desktop windowing then DeX follows. We still have to test top/bottom snapping.
- Position the mode honestly: it is great for scripting, editing, git and agents, but heavy builds are 3×-slower than a laptop with a ~15-min thermal cliff, so surface the thermal state and offer remote offload (SSH) for the big stuff.

## The keyboard problem (input layer)

The keyboard is the #1 complaint across every prior app. Our strategy works in layers:

1. **Own key row**: it is always present above the IME and in the tabletop bottom half, and it carries Esc, Tab, Ctrl and Alt as sticky modifiers, arrows, and a user-configurable symbol strip in the style of Termux's properties file. It injects through the native→bridge path rather than through IME tricks.
2. **IME coexistence**: Kern detects and respects split keyboards, which have been the default on the Fold inner screen since the Fold 5, and floating keyboards. Resizing is driven by `WindowInsetsCompat.ime()`, the cursor is always kept scrolled into view, and we recommend floating mode in tabletop.
3. **Hardware keyboard = first-class**: full VS Code chords arrive through native `dispatchKeyShortcutEvent` interception before the WebView, and we publish `onProvideKeyboardShortcuts`. A Bluetooth keyboard is the expected companion for long unfolded sessions, because every long-form account converges there, so we design for it rather than fight it.
4. **Typing minimisation**: AI chat-to-edit and agent runs are the primary heavy-input method, and voice input passes through. The best keyboard is the one you didn't need.
5. Optionally, and after v1, we could recommend or integrate a coding IME in the Unexpected-Keyboard style for power users.

## Continuity & survivability UX

- The app reopens to *exactly* where you were, restoring files, cursors, terminal scrollback and the agent session across fold transitions, app restarts and process death, with tmux semantics underneath.
- Sessions continue while the phone is pocketed, within Android's limits, and when the OS kills something anyway the UI says so plainly and offers reattach or rerun. The loss is never silent.
- Long operations post progress notifications, and "agent needs approval" arrives as a notification that deep-links to a cover-screen card.

## Onboarding (one-time, guided)

Sideloaded power tools die of setup friction, so onboarding is guided and happens once:

1. Install the bootstrap, showing progress and explaining what is happening and why.
2. Grant the battery optimisation exemption and remove the app from the Samsung sleep list, both through deep links.
3. Walk the user through the developer-options "disable child process restrictions" toggle, with a plain-English explanation of the phantom process killer.
4. Offer the "Continue apps on cover screen" opt-in.
5. Optionally, give Bluetooth keyboard pairing tips, install the Open VSX starter extension pack for the language of choice, and set up the git identity and SSH key generation.

## Visual design notes

- The default theme is AMOLED true black, which suits the 3000-nit panel and saves battery, and the matching workbench theme is synced over the bridge. A light theme for outdoor readability is one toggle away.
- Kern respects One UI 9's "app screen zoom", and we test all five levels.
- Touch targets are a minimum of 48dp everywhere we control, and the monospace font is JetBrains Mono with a ligatures toggle.
