# ux-research

## Summary
Real phone/tablet coding today succeeds only in narrow lanes: Termux/SSH terminal work, remote code-server/Codespaces in a browser, and (since 2025) AI-agent companion apps (Happy, Omnara, Claude iOS, GitHub Mobile agent review) where the phone is a monitoring/steering/approval surface rather than a typing surface. The consistent failure points are the on-screen keyboard eating the screen, Android's phantom-process killer murdering background sessions, thermal throttling under sustained load, and no local Docker. Foldables measurably change the equation — multiple first-hand accounts say the Fold-class inner screen turned Termux/Claude Code from "technically possible" to "genuinely enjoyable" — and the design space is now well mapped: posture-adaptive layouts (Flex mode content-top/controls-bottom), Gboard-style split keyboards, per-app fold/unfold continuity, and DeX/Android 16 desktop windowing as the "real work" escape hatch. Note: Z Fold 7 (and reportedly Fold 8) dropped S Pen support entirely, so stylus precision cannot be a design pillar.

## Key facts
- Android 12+ phantom process killer SIGKILLs forked child processes when the system-wide count exceeds 32, killing Termux shells/builds with '[Process completed (signal 9)]'; the disable toggle is hidden in developer feature flags and absent on many OEM builds (termux-app issue #2366) — any local-compute IDE must design around background death.
- Galaxy Z Fold 7 geometry: 8.0-inch inner screen at 2184x1968 (~1.1:1 near-square) and 6.5-inch 21:9 cover screen at 2520x1080 (GSMArena/TechRadar) — the inner screen is effectively two phone-widths side by side, the cover screen is now a normal narrow phone, not a wide squat panel.
- Z Fold 7 removed the digitizer (for thinness) and thus ALL S Pen support; Android Authority and Android Central report the Z Fold 8 also lacks it — stylus precision editing cannot be assumed on Fold8-class hardware.
- Every long-form phone-coding account converges on the same keyboard verdict: the IME consumes so much screen that serious sessions require either a folding Bluetooth hardware keyboard (jiby.tech carries an Arteck HB066) or a coding-specific IME — Unexpected Keyboard (swipe-to-corner symbols, Ctrl/Esc/Tab/arrows on home layer) is repeatedly praised on HN/Lobsters over Hacker's Keyboard; Termux's own user-definable extra-keys row is the in-app mitigation pattern.
- Gboard's split thumb-cluster keyboard became the DEFAULT on Fold-class inner displays from the Z Fold 5 onward; Samsung Keyboard also offers split and floating modes — an IDE should reserve layout space for these and add its own symbol/nav strip above the IME.
- First-hand foldable dev account (mfyz.com, Galaxy Fold then Pixel 9 Pro Fold): SSH-to-VPS + Claude Code + Terminus/Termux + Obsidian; the unfolded screen made terminal work 'native and actually comfortable' and turned Claude Code from technically possible into genuinely enjoyable; the wider cover screen was decisive for folded use.
- Samsung DeX week-long dev test (S24 Ultra): 45-min setup, git/SSH/Python 'snappy', but npm install ~3x slower than M2 Air, severe thermal throttle after ~15 min sustained compile, and Docker impossible (Android kernel lacks required cgroups/namespaces); proot Linux adds 20-50% I/O overhead — verdict: capable secondary environment for scripting and remote work only.
- Android 16 QPR1 shipped a developer preview of native desktop windowing on connected displays (GA in QPR3 for Pixel 8+), explicitly co-developed with Samsung to converge with DeX; as of June 2025 Google confirmed it works on tablet screens but NOT on foldables' inner screens (9to5Google).
- Samsung Flex mode design rules: usable hinge range 75-115 degrees, content on the top half, controls on the flat bottom half, animate the transition, and never place interactive elements on the crease; posture is read via Jetpack WindowManager (POSTURE_HALF_OPENED).
- Samsung app continuity is asymmetric: cover-to-inner handoff is automatic, but inner-to-cover requires the per-app opt-in 'Continue apps on cover screen' setting — an IDE must register for it and preserve exact editor/terminal state across the transition.
- The dominant 2025/26 mobile coding UX is agent supervision, not typing: Claude Code landed in the Claude iOS app (Oct 2025); Happy Coder is an open-source E2E-encrypted mobile companion for Claude Code/Codex; Omnara (YC S25) lets you 'monitor, steer, and approve' live agent sessions and review diffs with push notifications; GitHub Copilot coding agent can be assigned and its PRs reviewed from GitHub Mobile; Cursor cloud agents can be kicked off from a phone; Replit's rebuilt mobile app swipes between chat/tasks/preview and Agent 3 runs autonomously for up to 200 minutes.
- GitHub Mobile PR review is the proven cover-screen-scale workflow: unified diff with syntax highlighting works one-handed; split diffs render poorly at phone width; community guidance is to review only small/medium PRs on mobile — calibrating what an IDE's folded mode should attempt.
- Touch target consensus: Material 48dp (~9mm) / Apple 44pt (~7mm), research range 7-12mm; ~75% of interactions are thumb-driven and top corners of large screens are the worst reach zones — on a near-square unfolded screen, primary controls belong on bottom edges, not a desktop-style top toolbar.
- iPad-landscape lesson (April 2025 IDE survey): streamed VS Code (Codespaces/Blink/code-server) is the only approach preserving extensions and AI tooling, but 'the friction shows up in the input layer' — browser-tab IDEs lack a touch-tuned terminal and real keyboard focus management; pleasant tablet coding effectively requires an external keyboard.

## Details
## How developers actually code on phones today
Three proven lanes: (1) **Termux/SSH terminal work** — jiby.tech's nomad setup (Termux + Emacs + Hugo + pocket Bluetooth keyboard) shows it's viable but a "self-imposed limitation"; the XDA web-agency workflow and Henry Hale's account echo that it supplements rather than replaces a laptop. (2) **Remote code-server/Codespaces in a browser** — works, but it's "VS Code in a Safari tab": no touch-tuned terminal, broken keyboard focus, IME overlap. (3) **AI-agent supervision** (2025+) — mfyz.com's foldable account is the template: SSH to a VPS, Claude Code does the typing, phone does steering/review. What makes people give up: keyboard eats the screen, Android kills background processes (phantom process killer, >32 forked children → SIGKILL), thermals, no Docker, and tiny text.

## Keyboard problem
The IME is the #1 complaint everywhere. Mitigations, in order of observed effectiveness: hardware keyboard (every long-session account ends here); coding IMEs (Unexpected Keyboard's swipe-to-corner symbols + Ctrl/Esc/arrows on the home layer, beloved on HN/Lobsters); in-app extra-keys rows (Termux's user-definable strip is the canonical pattern — an IDE should own this); Gboard split (default on Fold inner screens since Fold 5) and Samsung floating keyboards; and minimizing typing entirely via AI chat/voice. Design implication: ship a built-in symbol/nav strip and a "terminal keys" row; never fight the IME for space.

## Fold postures
Flex mode rules (Samsung): 75–115°, content top / controls bottom, avoid the crease, animate transitions, read posture via Jetpack WindowManager. Almost no third-party productivity app does anything ambitious with tabletop mode — a top=editor/output, bottom=terminal+key-strip layout is genuinely novel territory. Unfolded (2184×1968, ~square): real users run Termux+browser split screen; two comfortable columns fit, three get cramped — file tree should be an overlay/rail, not a persistent third column. Keep interactive elements off the crease; align pane splits to it.

## Cover screen (21:9 narrow, one-handed)
Realistic scope proven by GitHub Mobile: unified diffs (split diffs fail at phone width), small/medium PR review, comment, approve; plus agent chat (Omnara/Happy pattern: push notification → read agent question → approve/redirect), git status/commit/push, and build/agent status glances. Not realistic: actual editing. Note the prompt's "squat wide cover screen" doesn't match shipping Folds — covers are tall/narrow, so one-thumb vertical flows, not side-by-side.

## Touch editing ergonomics
48dp/9mm minimum targets; 7–12mm research range; thumb reach worst at top corners — put toolbars at the bottom. Precise selection needs a magnifier (Android has a native Magnifier API) and draggable handles; multi-cursor should be an explicit mode/button, not a touch chord. S Pen is gone on Fold 7/8 — don't build on it. Acode/Replit show the gesture ceiling is low: swipe between panes/tabs is about as much gesture vocabulary as users retain.

## DeX / desktop windowing
DeX is where "real work" happens: git/SSH/scripting fine, but 3x slower npm installs vs M2 Air, thermal cliff ~15 min, no Docker, proot I/O penalty 20–50%. Android 16 QPR1→QPR3 brings native connected-display desktop windowing (Pixel 8+, Samsung co-developed, converging with DeX), though foldable inner-screen desktop mode was explicitly unsupported as of mid-2025. Implication: the IDE must fluidly become a keyboard-driven, resizable-pane desktop app on external display, while offloading heavy compute to remote.

## AI-first input & continuity
2025/26 pattern: phone = agent cockpit. Claude Code in Claude iOS (Oct 2025), Happy Coder (E2E-encrypted companion), Omnara (monitor/steer/approve + diff review + push), Copilot coding agent assignable/reviewable from GitHub Mobile, Cursor cloud agents from phone, Replit Agent 3 (200-min autonomous runs, chat/tasks/preview swipe nav). Continuity: Samsung cover→inner is automatic; inner→cover needs per-app opt-in ("Continue apps on cover screen"). Terminal survival requires tmux-style server sessions + foreground service, or remote sessions that outlive the app (mosh/tmux on VPS) — the only robust answer to the phantom killer.

## Ten UX decisions that determine daily usability (prioritized)
1. **Compute placement**: remote-first (VPS/cloud agent) with optional local Termux-class runtime — dictated by phantom killer, thermals, no Docker.
2. **Own the keyboard layer**: built-in symbol/terminal key strip, graceful IME (split/floating) coexistence, first-class hardware-keyboard shortcuts.
3. **AI as primary input**: chat-to-edit and agent runs are the default "typing"; hand-editing is the fallback, not the center.
4. **Review-and-approve as the core loop**: world-class unified diff at narrow width, per-hunk accept, one-thumb approve — this is what phones are demonstrably good at.
5. **Posture-adaptive layout system**: four distinct first-class modes (cover triage / unfolded 2-pane / tabletop flex editor-over-terminal / DeX desktop), driven by WindowSizeClass + posture APIs.
6. **Session persistence**: tmux-semantics sessions surviving app death, foreground-service protection, instant resume, agent-continues-while-pocketed with push notifications.
7. **Cover-screen scoping**: purpose-built one-hand flows (git ops, agent chat, diff review, status), never a shrunken IDE.
8. **Crease- and reach-aware placement**: splits aligned to fold, nothing interactive on the crease, primary controls in bottom/thumb zones, 48dp targets.
9. **Touch editing model**: magnifier + handles for selection, explicit multi-cursor mode, tiny stable gesture vocabulary.
10. **Continuity contract**: register for inner↔cover continuation, restore exact editor/terminal/scroll state across fold transitions and app restarts — broken resume is the silent daily-use killer.

## Confidence notes
Z Fold 8 details are pre/early-release reporting (Android Authority, Android Central) — S Pen absence on Fold 8 is reported by two outlets but not Samsung-official at research time; the prompt's premise of a "squat wide cover screen" conflicts with all shipping Folds (tall 21:9 covers) — treat that as a hypothetical form factor. DeX performance numbers (3x npm, 15-min thermal cliff) come from a single blogger's test (kunalganglani.com) and are directionally corroborated by an Alibaba product-insights piece but not independently benchmarked. Android 16 desktop-windowing-not-on-foldable-inner-screens was Google's position in June 2025; QPR3/Android 17 may have changed this — verify before relying on it. The HN thread on foldable Termux split-screen coding (item 25127756) returned HTTP 429, so its content is known only via search snippets. Phantom-process-killer behavior (32-process cap, hidden toggle, missing on some OEMs) is cross-confirmed across termux-app issue #2366 and multiple guides. Z Fold 7 screen specs cross-check across GSMArena, TechRadar, and Samsung. Several search-result summaries (Replit mobile rebuild details, Cursor cloud-agent mobile triggers) were not verified against primary vendor pages.
