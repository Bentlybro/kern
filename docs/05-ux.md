# 05 — UX Design

Grounded in [research/ux-research.md](research/ux-research.md) (real accounts of
foldable/phone coding) and [research/editor-tech.md](research/editor-tech.md) (input
constraints). Governing insight: **phones are provably great at reviewing, steering, and
terminal work; raw typing is the weak point** — so the design leads with review/agent/
terminal excellence and makes typing as good as Android allows.

## The four display modes

Mode selection is derived from window size class + `FoldingFeature` posture + DeX/desktop
state — never from device type. Transitions preserve exact state (the silent daily-use
killer is broken resume).

### 1. Cover Companion (folded, 5.5" squat 10:16 — one-handed)

Not a shrunken IDE — a purpose-built cockpit:

- **Agent cockpit**: live agent/terminal output tail; "agent needs you" question cards
  with approve/deny/reply; push notifications drive re-entry.
- **Git ops**: status, stage, commit (with AI-suggested message), push/pull — the
  GitHub-Mobile-proven loop.
- **Diff review**: unified diffs only (split diffs fail at this width), per-hunk
  accept/revert, syntax highlighted.
- **Status board**: running sessions, build results, battery/thermal state.
- Layout: single column, bottom-anchored actions (short screen ⇒ vertical space is
  precious; thumb lives at the bottom).
- Requires onboarding to enable Samsung's "Continue apps on cover screen" for
  inner→cover continuity.

### 2. Unfolded IDE (7.6" 4:3 landscape-first — the main event)

- Full VS Code workbench. Default arrangement: editor + right-or-bottom panel
  (terminal); file tree as the workbench's collapsible sidebar — two comfortable
  columns, never three.
- **Bottom-first chrome**: our native key row and mode controls sit at the bottom
  (thumb-reach research: top corners are the dead zone; Material 48dp targets).
- Hinge-aware: when a physical crease is present, offer split alignment to the hinge
  (editor left / terminal right in book-ish grip).
- Touch editing upgrades over stock workbench: long-press selection with Android
  `Magnifier`, explicit multi-cursor mode toggle in the key row, tap-gutter breakpoint
  affordances sized to 48dp.
- Keep gesture vocabulary tiny (research ceiling): swipe between editor groups /
  terminal tabs, two-finger scroll in terminal. Nothing exotic.

### 3. Tabletop / Flex (half-folded, hinge horizontal — the "laptop")

The flagship differentiated mode (75–115° hinge):

- **Top half (vertical)**: editor or agent output — content zone.
- **Bottom half (flat)**: terminal + our key row, or key row + REPL — control zone.
  Nothing interactive on the crease; panes align to `FoldingFeature.bounds`.
- This is a *self-contained pocket laptop*: no kickstand, no keyboard, usable on a
  train tray. No desktop IDE and no current mobile app does this seriously — genuinely
  novel territory.
- Implementation: workbench panel repositioning via the bridge extension +
  native bottom surface; animate posture transitions.

### 4. DeX / Desktop (external display or desktop windowing)

- The workbench is already a desktop app — this mode mostly means *getting out of the
  way*: full hardware-keyboard fidelity, resizable freeform windows
  (`resizeableActivity=true`, density-change handling), mouse hover/right-click/pointer
  icons, no mobile chrome.
- One UI 9 DeX is rebuilt on Android desktop windowing — optimize for stock desktop
  windowing and DeX follows. Test top/bottom snapping.
- Position honestly: great for scripting/edit/git/agents; heavy builds are 3×-slower
  than a laptop with a ~15-min thermal cliff — surface thermal state, offer remote
  offload (SSH) for the big stuff.

## The keyboard problem (input layer)

The #1 complaint across every prior app. Our strategy, in layers:

1. **Own key row** (always present above IME / in tabletop bottom half): Esc, Tab,
   Ctrl/Alt as sticky modifiers, arrows, and a user-configurable symbol strip
   (Termux-properties-style). Injects via the native→bridge path, not IME tricks.
2. **IME coexistence**: detect and respect split (default on Fold inner since Fold 5)
   and floating keyboards; `WindowInsetsCompat.ime()`-driven resize; always keep cursor
   scrolled into view; recommend floating mode in tabletop.
3. **Hardware keyboard = first-class**: full VS Code chords via native
   `dispatchKeyShortcutEvent` interception before the WebView; publish
   `onProvideKeyboardShortcuts`; Bluetooth keyboard is the expected companion for long
   unfolded sessions (every long-form account converges there — design for it, don't
   fight it).
4. **Typing minimization**: AI chat-to-edit and agent runs as the primary heavy-input
   method; voice input passthrough. The best keyboard is the one you didn't need.
5. (Optional, post-v1) Recommend/integrate a coding IME (Unexpected-Keyboard-style) for
   power users.

## Continuity & survivability UX

- Reopen to *exactly* where you were: files, cursors, terminal scrollback, agent
  session — across fold transitions, app restarts, and process death (tmux semantics
  underneath).
- Sessions continue while pocketed (within Android's limits); when the OS kills
  something anyway, the UI says so plainly and offers reattach/rerun — never silent
  loss.
- Long operations post progress notifications; "agent needs approval" is a
  notification → cover-screen card deep link.

## Onboarding (one-time, guided)

Because sideloaded power tools die of setup friction:

1. Install bootstrap (progress + what/why).
2. Battery optimization exemption + remove from Samsung sleep list (deep links).
3. Developer-options "disable child process restrictions" walkthrough (with plain-
   English explanation of the phantom process killer).
4. "Continue apps on cover screen" opt-in.
5. Optional: Bluetooth keyboard pairing tips, Open VSX starter extension pack
   (language of choice), git identity + SSH key generation.

## Visual design notes

- AMOLED-true-black theme default (3000-nit panel, battery), matching workbench theme
  synced over the bridge; light theme for outdoor readability one toggle away.
- Respect One UI 9 "app screen zoom" — test all five levels.
- 48dp minimum touch targets everywhere we control; monospace: JetBrains Mono w/
  ligatures toggle.
